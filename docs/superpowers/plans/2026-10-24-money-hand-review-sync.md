## B. 完整流水记录构造

- [ ] 定义 `hand_review` v1记录构造/解析纯函数，输入为已完成不可变CompletedHand。
- [ ] body包含摘要和完整紧凑JSON段；payload只放版本、session/hand/table/hand_id及格式索引。
- [ ] 用 `dz-pk:hand_review:{sessionId}:{handNumber}` 固定client_key；created_at固定为endedAt。
- [ ] 保留所有底牌、行动金额/牌面快照、真实NPC上下文/assumptions、派彩/退款/初末筹码，不包含deck和未发牌。
- [ ] 校验必要字段；旧完整档案保留原值，无法完整还原的旧文本不补造。
- [ ] 验证JSON还原深度相等，测典型/高行动数UTF-8字节大小；超限保留失败状态，不截断全文。

出口：一条记录足以完整还原本手事实，不依赖UI或若干game_log拼接。

## C. 结算事件与可靠outbox

- [ ] 新增独立handReviewSync/outbox，初始化一次，连接已完成历史新增事件；不能仅观察showdown阶段。
- [ ] 同步从已支付归档取得数据，最后NPC依据不漏；复制请求后独立于20手展示历史。
- [ ] 首次/刷新初始化等待历史hydration后补传本地已有完整20手，注册/补传与客户端/服务端均幂等；历史补传不弹回顾。
- [ ] 先持久化待发再请求，离桌/下一手保留；默认不打开回顾仍同步。
- [ ] 网络/超时/5xx可重试，确定性4xx保持失败且不堵后续；失败状态有简洁提示和手动重试。
- [ ] 确认201/200返回的source/kind、payload.hand_id及body还原的完整档案一致后标成功，保存record id；顶层无hand_id且不返回client_key；失去响应后重试不重复落库。
- [ ] outbox按client_key原子写入/删除（优先IndexedDB，localStorage整数组需等价跨标签锁）；ACK按当前队列key移除，每页面单flush，A期间B入队及多标签写入不能被旧数组覆盖。
- [ ] 存储不可用保留内存并显示状态；不在控制台打印body、payload、底牌或地址。
- [ ] 使用独立队列key，旧game_log协议/排队不被新功能覆盖；如共享发送工具，只抽取必要部分并补兼容验证。

主要落点：新增同步/队列/记录构造模块、main初始化、历史store必要事件、最近手牌/回顾状态展示。
