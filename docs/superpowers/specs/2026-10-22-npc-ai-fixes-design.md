## 2. 修复全下许可

### 问题与反例

`preflop.ts` 的 `attemptRaise()` 只在 `shortAllInOnly` 路径检查 `shoveOk`；普通路径将过大的目标改为 `maxRaiseTo`，直接返回全下。

已复现：激进 BB 拿 `As 4s`，大盲 10，当前下注 10、剩余 70，面对加到 30、上次增量 20。控制 RNG 为 0，触发 `attemptRaise(..., false)` 的诈唬分支，仍返回加到 80，即把剩余 70 全部投入。此时最小加注到 50，属于可以完整加注的情况。

### 要求

先归一化目标，再对最终金额检查许可：

- 保留最小加注与筹码上限规则。
- 无论原目标恰好等于还是超过上限，只要最终 `raiseTo === maxRaiseTo`，必须检查 `shoveOk`。
- `shoveOk = false` 且最终会全下时返回 `null`，让上层选择经过价格校验的跟注、过牌或弃牌。
- 不使用 `maxRaiseTo - 1` 等办法绕过风险控制；不要为了允许加注而制造近乎全下的金额。
- `minRaiseTo === maxRaiseTo` 也属于全下，必须经过许可。
- 保留合法强牌全下与已有的短码全下规则。全下加注许可与不足额全下跟注是两个不同的判断。

## 3. 补翻前价格与风险过滤

### 问题与反例

`callVsRaise / callVsReraise` 当前只检查是否在范围内。稳健 BTN 拿 `Js Ts`、剩余 1000，面对常规加到 20和面对加到 1000 的全下，都返回 `call`。仅修加注金额无法解决这条跟注路径。

### 数据与价格口径

复用 observation：`bigBlind / currentMaxBet / toCall / callCost / players / actorId`。

- `callCost` 为实际需要投入的筹码，不能用可能远大于本人筹码的 `toCall` 代替。
- `stackRisk = callCost / actor.chips`，分母是行动前剩余筹码；仅在 `callCost > 0` 且筹码有效时计算。
- `raiseBB = currentMaxBet / bigBlind`，描述面对的本街总下注尺度。
- 便宜跟注判断需要本人有资格争夺的底池。将拟议 `callCost` 加到本人的累计投入，复用 `splitPots()`，只累计本人有获胜资格的可争夺池，排除无资格边池与确定返还。
- `priceRatio = callCost / eligiblePotAfterCall` 仅是价格筛选指标；多人分池时不能把它称为完整行动 EV 或精确权益门槛。
- 不重复把本街 `currentBet` 加进 `pot`，不读取隐藏牌。

### 第一版价格档建议

使用小型可配置策略，区分 `normal / large / high-risk`。以下是可实施的初始护栏，不是 GTO 参数；允许开发时有依据地调整，并记录实际值与边界测试。

| 价格档 | 建议初始条件（从高风险往下匹配） |
| --- | --- |
| `high-risk` | `stackRisk >= 0.5` 或 `raiseBB >= 20` |
| `large` | `stackRisk >= 0.15` 或 `raiseBB > 5` |
| `normal` | 其余面对下注的情况 |

便宜短码例外：当 `callCost <= 2 * bigBlind` 且 `priceRatio <= 0.10` 时，可使用普通继续范围，避免因投入占剩余筹码比例很高而机械拒绝便宜跟注。例外仍须处于原有手牌继续范围、动作合法；不能借对手的巨额边池把价格“算便宜”。

对手标记为全下不自动决定价格档。例如对手只剩一个大盲的全下，和对手推进 100 个大盲，需要分别按实际价格判断。

### 继续范围与各条路径

`normal` 保留原有位置与加注次数对应的范围；`large / high-risk` 用额外的较紧范围过滤原范围。建议初始过滤范围：

| Profile | `large` 过滤范围 | `high-risk` 过滤范围 |
| --- | --- | --- |
| 稳健 `ai_0` | `TT+ / AQs+ / AKo` | `QQ+ / AKs / AKo` |
| 激进 `ai_1` | `99+ / AJs+ / AQo+ / KQs` | `JJ+ / AQs+ / AKo` |
| 保守 `ai_2` | `JJ+ / AQs+ / AKo` | `KK+ / AKs` |

过滤范围和阈值放在 profile 或明确的翻前配置里，不把数值散落在多个条件分支。它们是启发式风险护栏，不表示这些手牌面对任何对手都应投入全部筹码。

统一价格过滤必须覆盖：

- 面对一次加注的跟注。
- 面对再次加注的跟注。
- 价值 three-bet / four-bet。
- 加注因金额或许可失败后的回退跟注。

`large / high-risk` 禁用翻前诈唬再加注；`normal` 仍可按原 profile 的有限频率执行。普通继续范围、风险过滤、合法性和全下许可需要同时满足，不能互相替代。价格过滤应只收紧原范围，不意外新增手牌。

无需为这次修复新增翻前 Monte Carlo、大模型或对手范围学习。具体策略可以保持简单，但要证明面对 20 和 1000 筹码不再机械地作同一决定。

实际采用规格中的初始护栏，没有再调数值：

- `high-risk`：`stackRisk >= 0.5` 或 `raiseBB >= 20`。
- `large`：`stackRisk >= 0.15` 或 `raiseBB > 5`。等于 5BB 仍是 `normal`。
- `normal`：其余面对下注的情况。
- 便宜短码例外：`callCost <= 2 * bigBlind` 且 `priceRatio <= 0.10`。`priceRatio` 的分母只累计本人有资格争夺的池。
- 三个 profile 的 `largeContinue / highRiskContinue` 与上表一致，放在 `profiles.ts`。共用阈值在 `preflopPrice.ts` 的 `PREFLOP_PRICE`。

这些仍然是风险护栏，不是求解出的最优继续范围。

## 4. 修复翻后位置判断

### 问题与反例

`strategy.ts` 使用相对按钮的最小座位偏移。按钮仍 active 时结果碰巧正确；按钮弃牌、全下或未参与时，最小偏移指向最先行动的玩家。

反例：按钮 seat 0 已弃牌，只剩 seat 1 与 seat 3 active。seat 1 应先行动，seat 3 最后行动；旧实现给予 seat 1 完整位置优势、seat 3 位置惩罚。

### 要求

- 从按钮的下一座开始，按照真实座位顺序绕一圈。
- 仅 `status === 'active'` 的玩家参与“仍可行动”的位置比较；排除 folded、all-in、sitting-out。
- 最后一个仍可行动的玩家才有位置。
- 可使用 `(seat - dealerIndex - 1 + seatCount) % seatCount` 排序取最大值，或显式遍历座位；使用原座位总数，不能用过滤后的玩家数重新编号。
- 无 active 玩家返回 false；只有一个 active 玩家时该玩家是最后行动者。
- 同一个位置结果用于跟注惩罚、下注尺寸与诈唬频率，避免三个用途各算一套。
- 不修改翻前 `rangeSpot()` 的起始位置语义；本轮只修翻后判断。

## 5. 验收场景

### 全下许可

- 禁止全下时，目标等于上限、超过上限、最小加注等于上限、仅允许短码全下四种情况都不返回全下加注。
- 至少直接验证一次最终金额归一化 / 全下许可的辅助函数，避免新增价格过滤提前挡住分支，使测试虽然通过却没有覆盖 `shoveOk`。
- 激进 A4s 的反例不再触发禁止的全下，结果仍须通过合法动作校验。
- 稳健 BTN `76s`、20 筹码、开池目标 25，不再仅因开池范围命中而全下。
- AA 等满足策略条件的强牌合法全下仍能执行。

### 价格过滤

- 稳健 BTN JTs 面对常规 2–3BB 开池可按原范围继续；面对 100BB 全下退出，不投入整副剩余筹码。
- 再加注跟注、价值再加注、加注失败回退都不能绕过高风险过滤。
- 正常档保留既有风格区别；高风险档与大额档禁用诈唬再加注。
- 低实际成本、良好主池价格的短码全下跟注有正向用例。
- 相同短码用例再添加本人无资格争夺的巨大边池，便宜跟注指标不变；不因为边池看起来很大而放宽策略。
- 边界值（5BB / 20BB、15% / 50%、2BB / 10% 便宜例外）按实际配置测试。

### 翻后位置

- 按钮 active 时按钮最后行动。
- 按钮 folded / all-in / sitting-out 时，真正最后的 active 玩家有位置。
- 覆盖只剩两人、非连续活跃座位、按钮在最后一座的绕回、一个或零个 active 玩家。
- 用固定权益与 RNG 验证位置会正确影响行为：低权益 0.2、激进 profile、RNG 0.15 时，先行动玩家不因错误的位置优势诈唬，最后行动玩家仍可按完整频率诈唬。
- 直接验证位置辅助函数，并至少验证一次真实 `decide()` 输出，不只测几何排序。
