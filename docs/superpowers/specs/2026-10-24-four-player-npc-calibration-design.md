# 四人桌 NPC 防守与翻后练习校准规格

日期：2026-10-24（Asia/Shanghai）

状态：待实施。编写基线：`326b586`。配套计划：`docs/superpowers/plans/2026-10-24-four-player-npc-calibration.md`。

## 1. 本轮目标和范围

用户反馈的是“正常开池，其他人经常全弃”。本轮继续使用本人加三个 NPC 的四人桌，通过位置、价格和风格的合理策略，增加本人参与翻后决策的机会。

本轮实施：

1. 校准常规 2.5–3bb 开池后的防守，重点是大盲面对枪口/小盲，以及小盲面对开池。
2. 默认混合组合改成稳健、松凶、松跟；保守策略留在可选偏紧组合。
3. 将普通完整 3bet 与巨大开池分开定价，配置相应继续范围。
4. 修复影响上述策略的 AI 有效深度参考错误，并提供可重复的正确统计。

六人桌、增加座位、跨手偷盲识别/动态适应、CFR/RL/LLM 决策放到后续。其他回顾边池文案、听牌分类和整站 UI 改造不在本轮范围。

已完成的整数金额守卫、合法动作、资金结算、最近20手和完整 hand_review 同步继续有效；本轮不改记录库协议或数据库。开发/验证隔离真实资金和流水，不部署、不自动推送、不删除用户文件。

## 2. 已确认基线与统计边界

以下来自当前代码枚举和隔离模拟，并非用户最新云端牌局统计。

- 100bb，大盲面对枪口开到2.5bb，稳健/激进/保守弃牌约85.82%/78.43%/91.70%。上次主要放宽了大盲面对按钮的范围，其余场景仍窄。
- 按钮用本风格开池范围开到2.5bb、面对9bb再加注，以“已开池组合”为分母，三种风格弃牌约89.96%/90.72%/84.83%。当前最高注大于5bb即进入large，普通3bet受到巨大开池的同一护栏限制。
- 旧混合组合，100bb、人类随机底牌固定开到2.5bb，完整不放回发牌，三种NPC在剩余座位均衡轮换，每位置4,998次：

| 人类位置 | 给定前置条件 | 对手直接全弃 |
| --- | --- | ---: |
| UTG | 第一个行动 | 68.71%（3434/4998） |
| BTN | UTG已弃 | 46.12%（2305/4998） |
| SB | UTG/BTN已弃 | 78.07%（3902/4998） |

任一对手call/raise就判本次直接偷盲失败。前置弃牌是题设，不再按其牌力筛选；实际固定座次、本人开池范围会影响结果。联合全弃比例不能由单人弃牌率直接相乘得到。

旧500手experienceReport存在本人破产后未参与却被计入“人类见翻牌”的问题；其25%/23%不能用于本轮验收。实施前用本规格相同输入重跑基线，记录种子、配置版本、人数、分母和模式。

## 3. 风格、身份和默认配置

### 3.1 座位和策略分开

四个玩家ID仍为human、ai_0、ai_1、ai_2。保留旧策略ID ai_0=稳健、ai_1=激进（新显示标签可统一松凶）、ai_2=保守；新增独立策略ID `loose_passive`，不能将旧ai_2策略重新定义成松跟。

默认mixed组合：

| 座位ID | profileId | 名称/风格 |
| --- | --- | --- |
| ai_0 | ai_0 | 德州老手 / 稳健 |
| ai_1 | ai_1 | 激进小伙 / 松凶 |
| ai_2 | loose_passive | 松跟玩家 / 松跟 |

既有loose和tight配置键继续可用：偏松沿用松凶组合；偏紧保留保守组合。大厅加简洁的组合说明即可，不新增向导。

扩展ProfileId、PROFILES、DEFEND、profileFor及相关遍历；未知ID的既有兜底与已注册新策略要区分。执行仍优先取player.profileId，不能仅凭actorId选策略。

冻结baseline里的策略ID类型限定为原三种，参数保留原样；主ProfileId扩展后，不能给旧对照表补造松跟，也不能将Object.values(PROFILES)仍假定成三个元素。旧三风格代表牌测试显式选择旧ID，新增松跟独立测试。

### 3.2 松跟必须有独立行为

配置独立的开池/平跟、防守、面对3bet、短深筹范围和翻后参数。常规价格下继续较宽、平跟为主、少空气诈唬、较低混合3bet；AA/KK等强牌仍可依法价值加注。

允许松跟型以部分合理中等牌平跟入池，包括补小盲；免费行动仍可过牌。翻后按照本人底牌、公开信息和现有权益/价格模型决策，提供更多价值下注和听牌练习机会。不能通过全牌型跟注、强制制造翻牌、读取对手牌或临时改随机数达成指标。

每手保存实际配置版本，提升RANGE_CONFIG_VERSION。npcConfigVersion作为TableConfig/SessionSnapshot的可选字段：新选择生成配置时写当前版本，sessionFromTable复制已有版本；旧配置缺字段时继续缺失，不能在startHand时补成当前版本。已入座旧会话的NPC身份不因大厅新默认而被重配。

## 4. 常规开池防守校准

按本人位置、完整开池者位置、价格、有效深度配置，保留call与raise两种继续方式。四人桌UTG只有一人位于按钮之前，不照搬长桌早期位置图表。既有稳健/松凶开池结构可做必要的小幅配套校准，新增松跟要有完整开池和平跟表。

以下为100bb、2.5/3bb常规开池、1326实体组合加权的首版训练参数目标，属于启发式校准，非GTO解：

| BB面对的开池位置 | 稳健总继续 | 松凶总继续 | 松跟总继续 |
| --- | ---: | ---: | ---: |
| UTG | 25–40% | 30–45% | 40–55% |
| BTN | 40–55% | 50–65% | 55–70% |
| SB | 35–50% | 45–60% | 50–65% |

总继续=call+raise，不包括盲注和免费check。同输入松凶总继续应比稳健至少高5个百分点；松跟总继续不低于松凶，且call/总继续至少70%；松凶的3bet频率应明显高于松跟（至少5个百分点）。保守仍可较紧，单独报告，不套用松跟目标。本轮新防守区间替代旧训练规格对应区间，其余能力继续沿用已有验收。

同步输出SB对UTG/BTN、BTN对UTG、各位置首入池/平跟矩阵；小盲不能复制大盲表。至少保留位置差异和合理的底部弃牌，例如72o面对正常开池会弃，免费行动时会check。代表牌案例和价格/合法性回归优先于汇总百分比；若需小幅调整目标，更新规格及报告说明理由，不能只删断言或运行时补出call。

40/100/200bb分别提供范围及报告。短筹平跟按真实对局风险收紧；深筹许可不被无关短码压掉。无需要求每一个场景随深度严格单调，需有可解释的代表牌差异。

## 5. 完整加注层级与3bet价格

### 5.1 从公开行动识别层级

在observation/公共StreetSummary中提供本街完整开池、完整3bet的金额/行动者及完整加注次数等最小上下文。可从streetActions按合法最小增量推导或在动作时维护；要区分post、完整raise和不足额全下。

当前raw raiseCount及lastRaiserId会把不足额全下当成新加注，不可仅靠它判定3bet或更换参考对手。公共摘要不读取liveHand隐藏牌、deck或其他人底牌。保留canRaise/shortAllInOnly对是否重新开放加注的最终约束。

### 5.2 分档规则

保留normal/large/high-risk三档，增加公开的动作语境；不必增加记录库kind或请求字段。

| 场景 | 定价规则 |
| --- | --- |
| 首次开池 | 继续保留大于5bb为large、至少20bb为high-risk |
| 完整3bet | 前一完整开池正常（不超过5bb）、3bet目标不超过其约4倍（按整数筹码取整）、总目标小于20bb、实际跟注占本人剩余筹码小于15%，可为normal |
| 异常3bet | 前一开池已大额、倍数超限或实际跟注风险至少15%，为large |
| 任意动作高风险 | 总目标至少20bb或实际跟注风险至少50%，high-risk优先 |
| 4bet及以上/信息不足 | 本轮保留较保守的价格策略，不能随3bet一起全面放宽；缺信息记录保守原因 |

实际跟注额使用callCost=min(chips,toCall)，风险分母是行动前剩余筹码。极便宜跟注例外仍只允许合理便宜继续，不自动授权投机全下或无权限加注。

保留松凶现有3.5bb开池尺度；正常3bet判断必须覆盖2.5→10、3→12、3.5→14bb，不能用统一12bb上限重新误伤它。

### 5.3 独立继续范围

普通3bet用本人的开池/冷跟身份、位置、深度和价格选继续范围，不能只取消large护栏就让所有牌继续。自己已经开池、尚未入池的冷玩家、曾经冷跟的玩家分别处理；4bet价值牌与平跟牌保持区分。

100bb、BTN自身已开池组合、面对约3–4倍正常3bet时，稳健/松凶总继续先以30–50%为校准目标；统计同时列call与4bet。松跟和保守按其实际开池组成独立报告和代表牌校验，不硬套同一比例。40bb及200bb另测。

关键回归：6bb巨大开池仍large；100/200bb的2.5→10、3→12、3.5→14按常规3bet处理；40bb的2.5→10因实际跟注风险仍会收紧；2.5→20仍high-risk；无再加注权限/不足额全下合法性保持正确。

## 6. AI有效深度：本轮前置修复

当前effectiveStackBb取所有仍在局对手的最短筹码，会让一个0.5bb全下小盲把200bb按钮/大盲之间的争夺误判成short。

最小修复：面对开池/3bet，以真正定价的最近完整加注者与本人可覆盖的总筹码为参考；不足额全下者不覆盖该身份。未开池而仍有可行动对手时，以本人能参与的最大有效深度为开池参考，不取全桌最短值；只有全下对手时按实际需要匹配的对象处理。

明确记录referenceOpponentId、effectiveStackBb及本次动作语境，作为新诊断/实际NPC上下文的可选兼容字段；它们只解释策略参考，不删除任何all-in参与者，不改变真实派彩、可争夺池或权益计算资格。无需新增多人求解器或重做整套价格UI。

必要用例：BTN/BB均200bb，小盲0.5bb盲注全下，BTN开到2.5bb，BB应使用深筹主对局；真实完整开池者改40bb则应按短筹参考。弃牌/坐出玩家不压缩参考深度，短不足额全下不重置完整加注者。

## 7. 回顾和流水兼容

新名称/profile、实际原因、价格语境和深度参考按执行时绑定，再进入已完成档案。更新reasonText及必要的简洁展示，避免将新原因码显示成原始英文。

新诊断字段经AIDiagnosis→contextFor→NpcActionContext→CompletedHand显式传递；上传校验在可选字段存在时检查其结构，缺字段仍接受旧档案。新决策无参考对手时可明确null，不能给旧档案事后补出当时不存在的依据。

旧config.npcs、seats及actions[].npc保留原快照，旧保守大叔仍是保守；不重写旧本地历史、已入队请求、流水body或client_key。新增可选字段沿用CompletedHand/hand_review v1兼容格式，新档案完整JSON构造/解析后深度相等，旧档案缺字段也能读取。保存/同步仍在整手支付并归档后进行，默认不开回顾也同步。

## 8. 量化验收

### 8.1 组合矩阵

对1326实体组合用分支权重统计，不按169类别等权，也不只抽一次随机分支。覆盖全部注册profile、关键开池者/防守者、2.5/3bb及40/100/200bb；每行fold/check/call/raise合计100%。3bet继续分母是该风格实际开池组合，并另报冷玩家场景。

### 8.2 联合全弃

重跑第2节同口径场景：完整不放回发牌、每位置至少4998次、三种风格六种座位分配均衡、固定种子20261024并用20261025复验，按实际顺序执行，任一call/raise即停止本次直接偷盲统计。分别测旧混合身份（稳健/松凶/保守）和新默认身份（稳健/松凶/松跟），区分调范围与换组合的贡献。

100bb新默认、正常2.5/3bb开池，联合全弃首版参考上限：UTG55%、BTN45%、SB60%。报告写清前置弃牌给定、本人随机底牌不筛开池范围、座位轮换与实际固定座次的差异。这些是训练体验目标，不承诺每几手一定翻牌。

### 8.3 本人参与翻牌

使用固定人类基线策略，逐手恢复同一买入深度，按钮正常轮转，先只模拟翻前，到flop或全弃结束即完成该样本，不需要跑大量翻后权益抽样。两个种子各至少2000手，100bb新旧配置同输入对照，并补40/200bb诊断结果。

固定人类翻前OPEN：77+、ATs+、AJo+、KQs、KJs、QJs、JTs；无人开池开2.5bb。CALL：22+、A9s+、ATo+、KTs+、KQo、QJs、JTs、T9s、98s，面对加注且实际跟注不超过4bb时跟注，其余按合法check/fold。此策略仅作为固定对照，不是给用户的最优打法建议。

分母只含本人获发两张牌并实际参与的手；本人见翻牌要求其未在翻前弃牌、翻牌发出时仍active/all-in。本人坐出或破产不能被算“没弃牌所以见翻牌”。分别输出全桌翻牌率、本人翻牌率、按座位主动入池（不含盲注）、开池后全弃及call/3bet构成。

100bb新默认本人翻牌率须高于同口径基线；15%是非阻断的首版体验参考，未达到时列出位置、call/raise和价格分解及调整理由。正常价防守和代表牌正确性优先。不同人类策略的比例独立说明，不能为了达到指标让机器人读取人类基线或强制跟注。

### 8.4 安全边界与交付

- 金额安全整数、最小加注、不完整全下、未开放再加注、分池及下一手筹码守恒回归通过。
- 大注/高投入风险继续受保护；72o面对常规开池能弃；松跟强牌能价值加注，免费行动不弃。
- 混合/偏松/偏紧均可入座；同一actorId=ai_2配loose_passive时实际使用新策略，诊断/回顾/流水profileId正确。
- 旧归档/新归档构造解析、最后NPC依据、完整同步及去重回归通过；不用真实流水做验证。
- 新报告使用独立校准文件，写出通过显式命令开启；旧experienceReport自动写出也改为显式开关，保留历史报告，避免全量测试覆盖它。
- 跑相关及全量测试、构建、lint，记录既有错误和新增结果；更新实施计划并按项目规则本地提交。

实现可以在以上边界内自主选择最小模块组织。验收输出必须包含实际频率、分母、代表牌行为和风险回归，不能仅凭“机器人名字变了”或某几手终于翻牌判定完成。
